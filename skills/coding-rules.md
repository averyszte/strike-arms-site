# Coding Rules

## General Standards
- Preserve existing design unless explicitly told to redesign
- Make targeted edits only
- Do not rewrite entire files unnecessarily
- Reuse existing components and patterns before creating new ones
- Keep components modular and scalable
- Avoid duplicate logic
- Keep code readable and production-ready

## React + Vite Standards
- Use React + Vite architecture
- Prefer reusable components, but do not make every site feel the same
- Keep routing clean and scalable
- Use lazy loading where appropriate
- Avoid unnecessary rerenders
- Use proper loading and error states
- Maintain responsive behavior on all devices

## Performance
- Optimize image size and format
- Lazy-load non-critical content
- Code in a way that avoids excessive Supabase requests
- Minimize unnecessary dependencies
- Maintain good Lighthouse/PageSpeed scores

## Styling
- Mobile-first always
- Maintain clean spacing
- Preserve visual hierarchy
- Avoid cluttered layouts
- Avoid generic, average React or AI-generated sections
- Use smooth hover transitions sparingly

## Security
- Never expose secret keys
- Use environment variables correctly
- Respect Supabase RLS policies
- Preserve authentication security
- Validate user input

## Workflow
- GitHub is the source of truth
- Cursor is the primary development environment
- Replit is mainly for rapid prototyping
- Cloudflare Pages is used for deployment
- Inspect before editing
- Plan before implementing major changes
